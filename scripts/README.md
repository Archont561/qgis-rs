# scripts/

**Repository-wide automation is not here — it is `crates/xtask`.**
The gate, the C++ and TOML lints, the npm contents check, the qgis-sys
scaffolder, the libqca repair, the CI failure summary and the whole release
pipeline are subcommands of one program, reached through one pixi task:

```bash
pixi run xtask ci [--no-coverage]
pixi run xtask check-cpp [files...]
pixi run xtask format-cpp
pixi run xtask clang-tidy
pixi run xtask lint-toml [files...]
pixi run xtask pack-check <package-dir> <required...>
pixi run xtask scaffold <layer> <concept> <QgisClass> <short_name>
pixi run xtask setup-qca
pixi run xtask ci-failure-summary <log>
pixi run xtask release <verify-version|prepare|build-artifacts|checksums|publish-crates|publish-github-packages>
```

Why: a bash file that four manifests call by path is a dependency none of them
can type-check, its arguments are documented only in a comment, and nothing
tests it. A subcommand is parsed by clap, compiled by the same `cargo` the
project already needs, linted by clippy, and covered by `cargo test -p xtask`.
See [`.knowledge/decisions/D10-xtask-over-shell-scripts.md`](../.knowledge/decisions/D10-xtask-over-shell-scripts.md).

## What is still here, and why

| File | Called by | Why it is not an xtask subcommand |
| --- | --- | --- |
| `version.ts` | `pixi run version[-check\|-set]` | The one tool that rewrites every manifest in the repository (JSON, TOML, YAML). It predates xtask, is already the single source of truth for the version, and `xtask release` calls `pixi run version` rather than owning a second implementation. |

That is the whole directory. Everything else that used to be a `.sh` file here
is gone:

* **The repository verbs** became `xtask` subcommands, above.
* **The package verbs** became single-line scripts in each package's own
  `package.json` — `crates/package.json` for the Cargo workspace,
  `py-packages/*/package.json` for the Python distributions. They are no longer
  *this* directory's business: turbo already runs them with the package
  directory as the working directory, and `pixi run` preserves it, so a package
  verb needs no `cd` to the repository root and therefore no wrapper. See
  `README.md`.
* **`lib.sh`**, whose only job was that `cd`, went with them.

The airlock bootstrap that also used to live here is `restore.sh`: it runs on
a machine that has no cargo yet, so it cannot be an xtask subcommand — building
xtask would require the environment the script exists to restore. It is
generated by `pixi sandbox init --script-path scripts/restore.sh` and is never
edited; its header carries the full invocation.
