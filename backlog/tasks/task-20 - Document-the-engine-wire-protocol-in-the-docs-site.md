## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The repository now speaks one versioned JSON protocol across every FFI boundary (D09), but the docs site still describes the per-language APIs only. Publish a reference page for the protocol itself: the request/response envelope, `transport_version` and what a mismatch does, the full operation table with payload and result shapes, and the `ErrorKind` list with how each client maps it to a native exception.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-06: The page is `docs/src/content/docs/reference/wire-protocol.mdx`, reachable from the autogenerated API Reference sidebar and linked from `reference/index.mdx` under a new "The transport" heading. AC#1 is the Envelope section: `EngineRequest` and `EngineResponse` field-by-field, `TRANSPORT_VERSION` with the reason it is a second number next to `qgis_render::VERSION`, what an engine does with a version it does not know, and the path-based binary-artifact rule from D12 §3.

2026-10-06: The decision that shaped the task: a hand-written page listing 29 operations and 16 error kinds is a second copy of two lists that already exist in `qgis-protocol`, and the usual fate of a second copy is to be right on the day it is written. So the prose is hand-written but the *names* are gated. `pixi run xtask check-protocol-docs` links `qgis-protocol` and compares the published tables against `Operation::all()` and `ErrorKind::all()` in **both** directions — an operation the engine serves and the page omits fails, and so does an operation the page invents. The page marks its machine-checked regions with MDX comments (`{/* protocol-docs:operations:begin */}`) so the prose around them stays free to change.

2026-10-06: AC#3 is checked rather than asserted. The Python column is compared against `_EXCEPTION_BY_KIND` parsed out of `py-packages/qgis-rs/python/qgis_rs/_transport.py`, with `InvalidInput` as the documented fallback for every kind the client does not map specially — so the table cannot claim a mapping the client does not implement. The gate carries no copy of that mapping itself, because a gate holding its own copy of the thing it checks would simply certify the drift. The JavaScript column is checked for `EngineError`, which is the one class that client throws; the page additionally documents the two kinds the JS client can raise *without* the engine having spoken (`unsupported_transport` on a version mismatch it detects locally, `invalid_request` when a failure envelope carries no kind).

2026-10-06: `ErrorKind` needed an authoritative list for the gate to read, and had two hand-maintained ones (the enum and the `as_str` match) that a new variant could leave disagreeing. Both now come from one `error_kinds!` macro invocation, one line per kind, which also generates the new `ErrorKind::all()`. The pre-existing per-variant rstest cases still pass unchanged and now additionally assert membership in `all()`.

2026-10-06: Evidence the gate bites, not just that it runs. Dropping the `tile_bounds` row reports "operation `tile_bounds` is served by the engine but has no row in the operations table" and exits 1; changing the `io` row's Python column to `InvalidInput` reports "error kind `io` becomes `EngineIOError` in py-packages/qgis-rs/python/qgis_rs/_transport.py, but the table says `InvalidInput`" and exits 1. `crates/xtask/tests/protocol_docs.rs` is eleven tests, nine of which damage a known-good page in one specific way and assert the complaint names that damage.

2026-10-06: Wired into the gate as `RepoLint::CheckProtocolDocs`, last in `REPO_LINTS`, so it runs in the `repo` CI lane in milliseconds before any compile. `crates/xtask/tests/ci.rs` and `crates/xtask/tests/cli.rs` were updated to expect it, which is what keeps a lane from silently dropping it. `xtask` gained a `qgis-protocol` workspace path dependency — one line in `Cargo.lock`, no registry access, which matters on an airlocked sandbox.

2026-10-06: The Astro docs build goes 49 -> 50 pages and stays green.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
The engine wire protocol has a reference page, and the page cannot quietly go stale. `docs/src/content/docs/reference/wire-protocol.mdx` documents the `EngineRequest`/`EngineResponse` envelope, `TRANSPORT_VERSION` and what a mismatch does, all 29 operations with payload and result shapes, all 16 error kinds with the Python exception and the JavaScript `EngineError` each becomes, the `snake_case`-on-the-wire rule and the fact that the JavaScript client renames at its own edge in `ts-packages/qgis-node/src/index.js` while Python does not rename at all. What makes it a reference rather than a snapshot is `pixi run xtask check-protocol-docs`: it links `qgis-protocol`, compares both tables against `Operation::all()` and `ErrorKind::all()` in both directions, and checks the Python column against the mapping parsed out of the client's own source. It runs in the `repo` CI lane before any compile. `ErrorKind` now generates its variants, wire spellings and `all()` from one macro invocation instead of two hand-maintained lists.
