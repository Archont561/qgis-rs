# Documentation Site

The qgis-rs documentation site is built with [Astro Starlight](https://starlight.astro.build/) and located in `apps/docs/`.

## Architecture

```
apps/docs/
├── astro.config.mjs           # Starlight config (sidebar, social, logo)
├── package.json                # Astro + Starlight + sharp + TypeScript
├── tsconfig.json               # Strict TypeScript
├── src/
│   ├── assets/logo.svg         # QGIS + Rust gear logo
│   ├── styles/custom.css       # Theme overrides
│   └── content/docs/           # MDX documentation pages
│       ├── getting-started/
│       ├── concepts/
│       ├── guides/
│       ├── reference/
│       ├── cli/
│       └── server/
└── public/                     # Static assets
```

## Pixi Integration

The docs site has its own Pixi environment:

```toml
# pixi.toml
[feature.docs.dependencies]
bun = ">=1.0.0,<2"

[feature.docs.tasks]
docs-dev = { cmd = "bun run dev", cwd = "apps/docs" }
docs-build = { cmd = "bun run build", cwd = "apps/docs" }
docs-preview = { cmd = "bun run preview", cwd = "apps/docs" }

[environments]
docs = { features = ["docs"] }
```

### Running

```bash
# Activate docs environment
pixi shell -e docs

# Development server
pixi run docs-dev

# Production build
pixi run docs-build

# Preview production build
pixi run docs-preview
```

### Fallback (npm)

If Bun is unavailable, npm works identically:

```bash
cd apps/docs
npm install
npm run dev
npm run build
```

## Content Structure

### Sidebar (configured in astro.config.mjs)

| Section | Content |
|---------|---------|
| **Getting Started** | Introduction, Installation, Quick Start |
| **Core Concepts** | Architecture, API Design, QGIS Integration |
| **API Reference** | Auto-generated from `reference/` directory |
| **Guides** | Rendering Projects, Working with Layers, Plugin Development |
| **CLI** | Auto-generated from `cli/` directory |
| **Server** | Auto-generated from `server/` directory |

### Page Types

- **`.mdx`** — Markdown + JSX components (most pages)
- **`.md`** — Plain Markdown (simpler pages)

### Frontmatter

Every page requires YAML frontmatter:

```yaml
---
title: Page Title
description: SEO description
---
```

## Adding Documentation

1. Create a `.mdx` file in the appropriate `src/content/docs/` subdirectory
2. Add frontmatter (title + description)
3. Write content
4. Add to sidebar in `astro.config.mjs` (unless using `autogenerate`)

### Autogenerated Sections

The `reference/`, `cli/`, and `server/` sections use Starlight's `autogenerate` feature:

```js
{
  label: 'API Reference',
  autogenerate: { directory: 'reference' },
}
```

Pages in these directories appear automatically in sidebar order.

## Deployment

Build output goes to `apps/docs/dist/`. Deploy to any static hosting:

| Platform | Command |
|----------|---------|
| Netlify | Drag & drop `dist/` |
| Vercel | `vercel --prod` |
| GitHub Pages | Upload `dist/` to `gh-pages` branch |
| Cloudflare Pages | Connect repo, build `npm run build`, output `dist/` |
