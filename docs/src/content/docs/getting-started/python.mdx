# Python package

`qgis-py` is a thin Python API over the Rust core, shipped as a **PyO3 extension** (`qgis_py._core`). The Rust core runs or starts QGIS programmatically; the package has no command-line interface.

- **pip**: `pip install qgis-py` → `import qgis_py`
- **conda**: `conda install -c conda-forge qgis-py` → same, with optional QGIS backend

## Installation

### From PyPI (pip)

```bash
pip install qgis-py
```

What you get:

- `qgis_py` Python module (pure-Rust geometry + optional QGIS rendering)

Pre-built wheels for Linux x86_64, macOS arm64/x86_64, Windows x86_64. If no wheel matches, pip builds from source via `maturin` (requires Rust ≥1.96).

### From conda-forge

```bash
conda install -c conda-forge qgis-py
# or
pixi add qgis-py
mamba install -c conda-forge qgis-py
```

The conda-forge package can be built in two modes:

- **Lightweight (default)**: No QGIS dependency. Supports `info`, `tiles --dry-run`, `version`, and the Python API for tile planning. This is what `pip install qgis-py` gives you.
- **Full**: Depends on `qgis >=3.44.9`. Supports `render`, `tiles` (actual rendering), `export`, `serve`. Get it via `conda install -c conda-forge qgis qgis-py`.

### From source (development)

```bash
git clone https://github.com/Archont561/qgis-rust
cd qgis-rs

# Python dev with maturin
pip install maturin
(cd py-packages/qgis-py && maturin develop)

# Or via pixi (conda env with QGIS)
pixi install -e default
pixi run -e default py-test

# Test
python -m pytest py-packages/qgis-py/tests -q
```

## Python API

```python
from qgis_py import Project, Extent, TilePlan, ZoomRange, Crs, plan_tiles

# Open a project (cheap — only checks path, no QGIS needed)
project = Project.open("map.qgs")
print(project.path, project.format)

info = project.info()
print(info.to_dict())

# Pure-Rust geometry — native speed, no QGIS
extent = Extent.parse("14,50,15,51")
assert extent.width() == 1.0

crs = Crs.from_epsg(3857)
print(crs.auth_id, crs.is_projected())  # EPSG:3857 True

# Tile planning — counts tiles without rendering
zooms = ZoomRange.parse("10-14")
plan = TilePlan(extent, zooms)
print(f"Would render {plan.tile_count()} tiles")  # 4568
for level in plan.levels():
    print(f"z={level.zoom} {level.tile_count()} tiles")

# Fast function
total, levels = plan_tiles("14,50,15,51", "10-14")
print(total)  # 4568

# Rendering through the native QGIS backend
try:
    rendered = project.render("output.png", width=1920, height=1080)
    print(f"Wrote {rendered.path} ({rendered.bytes} bytes)")
except ValueError as e:
    print(f"QGIS rendering failed: {e}")
```

## Architecture

```
qgis-py wheel
├── qgis_py/
│   ├── __init__.py      → the public API
│   ├── _api.py          → Extent, Crs, Tile, TilePlan, ZoomRange, Project
│   ├── _transport.py    → invoke(): one JSON call into Rust, errors → exceptions
│   └── _core.so         → Rust cdylib (PyO3) — exposes exactly one function, invoke()
```

There is no pure-Python fallback: every number this package returns is computed
by Rust, and a second implementation would be a second set of answers. Without
a built `_core`, importing `qgis_py` raises.

- `crates/qgis-protocol` — the request/response envelope and the closed list of operations
- `crates/qgis-engine` — `invoke(request_json) -> response_json`, one arm per operation
- `crates/qgis-render` — pure Rust, no QGIS needed
- `py-packages/qgis-py` — the Python distribution (client, tests, maturin config)
- `py-packages/qgis-py/src-rust` — the PyO3 adapter

## Conda-forge

See `py-packages/qgis-py/recipes/qgis-py/` for the recipe. It builds the Python extension and installs it to site-packages.

To publish to conda-forge:

1. Fork https://github.com/conda-forge/staged-recipes
2. Copy `py-packages/qgis-py/recipes/qgis-py/` to `recipes/qgis-py/`
3. Open PR

| TilePlan 10-14 | 0.2ms | 3ms | 15× |
