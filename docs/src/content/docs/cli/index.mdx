# qgis-cli

The `qgis-cli` binary provides command-line access to qgis-rs rendering and serving capabilities.

## Commands

| Command | Description |
|---------|-------------|
| `version` | Report CLI, engine, transport, target and backend versions |
| `capabilities` | Discover operation availability and domain limits |
| `doctor` | Diagnose pure-engine readiness and optional QGIS support |
| [`render`](/cli/render) | Render a QGIS project to an image |
| [`tiles`](/cli/tiles) | Generate tile pyramids |
| [`batch`](/cli/batch) | Batch render multiple extents |
| [`info`](/cli/info) | Inspect a QGIS project |
| [`serve`](/cli/serve) | Start an HTTP map server |
| [`export`](/cli/export) | Export features from a layer |
| [`mcp`](/cli/mcp) | Serve the same capabilities as an MCP server for AI assistants |

:::note
`qgis-cli` is the command-line front end for the `qgis-render` and
`qgis-server` crates. Each subcommand maps onto a module in the
[API Reference](/reference/) — `render` onto [`render`](/reference/render),
`tiles` onto [`tiles`](/reference/tiles), `export` onto
[`features`](/reference/features), and `serve` onto
[`server`](/reference/server).
:::

## Discovery

```bash
qgis-cli version --json
qgis-cli capabilities --json
qgis-cli doctor --json
```

These read-only commands share a report containing `cli` (name and version),
`target` (OS and architecture), `engine` (version, transport version, backend,
limits and operation availability), `commands`, `command_note`, `status` and
`diagnosis`. Omit `--json` for human-readable output. The existing `--version`
flag still prints only the CLI name and version.

`commands` describes the parser surface, **not execution availability**.
`engine.operations` lists the protocol vocabulary with an `available` boolean
and a `reason` for unavailable routes. Native manager support alone does not
make an unimplemented engine route or CLI command available. In particular,
these discovery commands do not change the existing render/export/serve gates.

The backend report distinguishes `compiled` from live `available`, includes
`qgis_version` when available, and retains the backend `error` on failure.
Native builds probe through the manager's owner thread; pure builds do not load
QGIS. Reported limits are the enforced zoom and latitude domain limits, not
promises of worker, memory or cancellation controls.

For a pure Rust build, with no QGIS, Qt, Python, Node or WebEngine dependency:

```bash
cargo build -p qgis-cli --no-default-features
```

Successful reports exit **0**, including `doctor` when the optional backend is
absent and the pure engine is healthy. Argument errors exit **2** with diagnostics
on stderr. JSON stdout contains only the report; native-library diagnostics may
appear on stderr. Reports are deterministic for the same build and runtime
state and perform no implicit downloads or artifact writes.

`doctor` explains build/runtime requirements; it does not install dependencies,
scan profiles, or guarantee that a particular project/provider will work.
Validation, project-manifest inspection, new planning commands and resource
policies remain later TASK-41 slices.

## Installation

```bash
cargo install qgis-cli
```

Or build from source:

```bash
cargo build --release -p qgis-cli
```

## Quick Examples

```bash
# Render a project
qgis-cli render map.qgs -o map.png

# Generate tiles
qgis-cli tiles map.qgs -z 10-14 -b 14,50,15,51 -o ./tiles/

# Start a server
qgis-cli serve map.qgs --port 8080

# Inspect a project
qgis-cli info map.qgs

# Serve the same capabilities to an MCP client over stdio
qgis-cli mcp
```
